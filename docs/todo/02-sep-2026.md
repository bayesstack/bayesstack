# BayesStack Comprehensive Architecture Roadmap - September 2, 2026

This document details the complete end-to-end user stories, database schemas, authentication flows, and studio runtime requirements for BayesStack.

---

## 1. SuperAdmin Portal - In-Browser Database Studio (`apps/super`)
- [ ] **High-Density Data Studio (In-Browser PgAdmin Clone)**:
  - Live data tables rendering all PostgreSQL database tables dynamically.
  - Full CRUD controls directly from UI (Create, Read/Filter, Edit, Delete table rows).
  - Data table capabilities: Search, column sorting, pagination, multi-column filters.
  - Side SQL Query Runner drawer: Write custom SQL queries for selected tables and execute them live with tabular output.
  - Maximum efficiency & performance with optimistic UI updates.
  - *Note: Learning Library tab in SuperAdmin remains hidden/deferred for later.*

---

## 2. Multi-Tenant Identity, Dynamic Role Redirection & Auth Persistence
- [ ] **Subdomain & Tenant Verification**:
  - Extract tenant from hostname (`{tenant}.bayesstack.com` or `{tenant}.localhost`).
  - If tenant is invalid -> redirect to dynamic "Tenant Not Found" error page in `apps/auth`.
  - If tenant exists -> load tenant login/signup page.
- [ ] **Role-Based Dynamic Redirection (No Role Dropdown)**:
  - Remove manual role selector from login screen. Role is derived strictly from the database `users` record.
  - Seed Bayes Institute (`bayes`) tenant users with distinct role credentials:
    - Learner: `learner@bayes.edu` (`password123`)
    - Faculty: `faculty@bayes.edu` (`password123`)
    - Tenant Admin: `admin@bayes.edu` (`password123`)
    - SuperAdmin: `admin@bayesstack.com` (`admin123`)
  - Automatically redirect logged-in users based on DB role:
    - `learner` -> Learner Portal (`localhost:3001` or `/learner`)
    - `faculty` -> Faculty Portal (`localhost:3002` or `/faculty`)
    - `admin` -> Admin Portal (`localhost:3003` or `/admin`)
    - `superadmin` -> SuperAdmin Portal (`localhost:3005` or `/super`)
- [ ] **Auth Session Persistence (`/api/auth/me`)**:
  - Implement `/api/auth/me` session validation endpoint in FastAPI.
  - Set HttpOnly/TTL session cookies scoped to the tenant domain.
  - On subsequent visits to `{tenant}.localhost`, automatically check `/api/auth/me` and bypass login directly to the role frontend.
- [ ] **Clean Portal Landing Pages**:
  - Redesign and clean default landing screens for `apps/learner`, `apps/faculty`, and `apps/admin`.

## 4. 6-Tier Academic Content Hierarchy Schema & Database Engine
- [ ] **PostgreSQL ORM Models & Alembic Migrations**:
  1. `Tenant`: Institutional academic container (e.g. Bayes Institute).
  2. `Curriculum`: Ordered sequence of academic programs.
  3. `Program`: Ordered sequence of courses.
  4. `Course`: Ordered sequence of chapters.
  5. `Chapter`: Ordered sequence of concepts.
  6. `Concept`: Atomic learning unit containing ordered Studio instances.
- [ ] **Django Admin-Style Hierarchy Inspector**:
  - SuperAdmin database studio support for navigating and editing all 6 tiers of the academic graph.
- [ ] **Canonical Content Seeding**:
  - Seed baseline sample curriculum, programs, courses, chapters, and concepts for Bayes Institute.
  - **UpGrad Data Science Program Skeleton**:
    - Sample curriculum skeleton for client **UpGrad** (`UpGrad Executive PG Program in Data Science`).
    - Decide the content files that we will create for them, and thus how to upload those files to the system (studios and DB). 
  - **Bayes Institute Canonical Data Science Master Skeleton**:
    - Seed canonical platform master curriculum (`Bayes Canonical AI/ML Curriculum`).
    - Chapters and concepts designed for institutional borrowing and cross-tenant reuse.

## 5. Concept Studio Runtime Screens (Coding & Video Studios)
- [ ] **Standalone Concept Launch & Preview**:
  - Ability to browse concepts in the Learning Library and click "Launch Studio".

- [ ] **Studio 1: Coding Studio**:

- [ ] **Studio 2: Video Learning Studio**:

## 6. Faculty Course Borrowing, Composition & Publishing Flow
- [ ] **Faculty Portal Studio (`apps/faculty`)**:
  - Faculty browse canonical platform concepts and borrow/sequence concepts into a course for their university.
  - Faculty click **Publish** to release the course to their institution.
- [ ] **Institutional Visibility**:
  - Published course becomes immediately visible on the Learner Portal (`apps/learner`) for enrolled students of that tenant.

---

## 7. Student Learning Experience & Telemetry Events
- [ ] **Learner Progress Experience (`apps/learner`)**:
  - Learner opens published course, navigates chapters, and completes Concept Studios.
- [ ] **Learning Event Telemetry**:
  - Emit and record student learning events (`concept_started`, `code_executed`, `concept_completed`) to track progress.
