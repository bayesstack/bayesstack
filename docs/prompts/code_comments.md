# Prompt: Code Comments Guideline

Add comments only when they improve a future developer’s understanding of the code. Never comment merely to increase coverage or restate what the code obviously does. Prefer comments on blocks, decisions, non-obvious lines, tricky logic, workarounds, assumptions, constraints, and the "why" behind an implementation, especially where a reasonable developer might otherwise pause and wonder why it was done this way. Write comments as a human developer would: concise, specific, contextual, and natural. Explain intent, trade-offs, edge cases, or surprising behavior rather than translating code into English. If the code is already self-explanatory, leave it uncommented. The goal is that a developer returning to this code months later can quickly understand both what is happening and why it was implemented this way.
